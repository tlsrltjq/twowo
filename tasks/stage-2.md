# 2단계 작업 컨텍스트 — 캘린더 + 사진

## 지금 단계: 2단계 — 캘린더 + 사진

> **범위(ADR-018)**: 1차 = **📅 월간 + 🖼️ 사진 2뷰**. 🏃 운동 / 💑 데이트 뷰는 **2차**(데이터 쌓인 뒤). 사진은 **라이브러리 선택 + 압축 + EXIF(GPS) 제거**(1차). 인앱 카메라는 2차로 미뤄도 됨.

## 설계 원칙
- 이벤트 타입(date / exercise / general)으로 구분, 데이터는 하나 (타입 자체는 1차부터 저장)
- 뷰만 전환 — **1차는 캘린더 뷰 / 사진 뷰 2개**. 운동/데이트 뷰는 2차
- 사진은 라이브러리 선택 → 압축 + EXIF 제거 후 업로드 (인앱 카메라 2차)
- 모든 이벤트는 coupleId 기준으로 실시간 공유

## 완료 기준 — 1차
- 커플 양쪽이 같은 이벤트 목록 실시간 조회 가능
- 이벤트(일정 타입) 추가/수정/삭제 후 Firestore 반영 및 화면 갱신
- 사진 업로드 후 썸네일이 리스트에 표시됨 (로딩 1초 이내)
- **업로드된 사진에 EXIF(GPS) 메타데이터 없음** — Storage 객체 확인
- 뷰 전환 탭(캘린더/사진) → 해당 뷰로 정상 필터링
- 사진 원본 크기 평균 500KB 이하 유지
- **이벤트 삭제 시 Storage 객체(원본/썸네일)도 함께 삭제됨** — Firebase 콘솔에서 고아 파일 0건 확인
- **단위 테스트 통과**: `core/storage/`, `core/calendar/deleteEvent` 테스트 green

## 완료 기준 — 2차
